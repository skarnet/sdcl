sdcl

What is it ?

SDCL, in uppercase, stands for Service Definition Configuration Language.

Every service manager has its own format to describe how services should be started and stopped: so, depending on the service manager, service definitions typically appear in what people call init scripts, boot scripts, init.d files, service directories, service definition directories, service files, or unit files.

This multiplicity of formats is normal, because every service manager does things slightly (or very) differently, and so, has different requirement for its input format. However, this locks distributions into a single service manager, or forces them to duplicate or triplicate packaging effort, with redundant data — which eventually always becomes inconsistent — if they want to offer their users a choice of service managers. And most services need the same basic features, that are provided by all the service managers; it is rare that a given service is tied to a feature that is only provided by a specific service manager. Most service definitions do the exact same basic things, no matter what service manager implements them. It would be beneficial to unify them.

SDCL is a text file format that does just that: it provides a service manager-agnostic way to write definitions. It is a configuration language, which means that it is purely declarative, and it supports all the basic features that current service managers provide. As service managers evolve and provide more features, SDCL will evolve as well.

sdcl, in lowercase, is this software package. It is an implementation of the SDCL language: it contains tools that read a set of text files in the SDCL format and output a set of files implementing the same service definitions, in the format of the chosen service manager.

sdcl is meant for distributions, or end users, so they can write their service definitions in SDCL and port them effortlessly to any service manager.

Installation

Requirements

  • A POSIX-compatible system with a standard C development environment.
  • GNU make, version 3.81 or later
  • skalibs version 2.16.0.0 or later. It's a build-time requirement. It's also a run-time requirement if you link against the shared version of the skalibs library.
