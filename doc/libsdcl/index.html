The sdcl library interface

General information

libsdcl is the library providing the necessary functions to parse and process a set of SDCL files, and then access their data in a convenient in-memory format.

Compiling

  • Make sure the sdcl headers are visible in your header search path.
  • Use #include <sdcl/sdcl.h>

Linking

  • Make sure the sdcl library, as well as the skalibs libraries, are visible in your library search path.
  • Link against -lsdcl -lskarnet
    • .
  • If you're linking dynamically, you may need to add -lpthread, and/or other -lfoo arguments depending on how your libc is organized.
  • If you're using pkg-config or equivalent, it should take care of all these annoyances for you.

Programming

Parsing a set of SDCL files

int sdcl_parse (sdcl_context_t *ctx, char const *files, size_t n, unsigned int verbosity, char const *progname, unsigned int flags)

  • ctx is a pointer to an already declared (preferrably in the stack) sdcl_context_t object, that must be initialized to the SDCL_CONTEXT_ZERO value.
  • files is an array of n file paths (relative or absolute) that are the SDCL files you want to read.
  • verbosity tells the function how verbose you want it to be:
    • 0 means it will only print fatal errors to stderr
    • 1 means it will print fatal errors and warnings to stderr
    • 2 means it will print more details to stderr about what it is doing
    • 3 will print a wild amount of details
    • 4 or more is for debugging.
  • progname is the name to prepend all printed messages with. It should be your executable's name.
  • flags is a bitfield. You can OR the following flags:
    • SDCL_PARSE_FLAG_FATAL: print "fatal" error messages on issues such as system call failure or syntax error, and exit the program
    • (other flags can be defined)
  • On success, the function returns 0, and all the data is stored in the ctx context.
  • On failure, the function returns a nonzero error code.
    • If the error code is positive, it is an errno: the underlying system had a problem. The printed messages, if any, said that the error was fatal. There isn't much for you to do but exit the program.
    • If the error code is negative, it means that the data fed to sdcl_parse is invalid. The code can be:
      • SDCL_PARSE_RETURN_SYNERR: syntax error.
      • SDCL_PARSE_RETURN_DEPCYCLE: a cycle was detected in the service dependencies.
      • (other error codes can be defined)

Accessing the data after parsing

size_t sdcl_services_count (sdcl_context_t const *ctx)

  • Returns the number of services defined in ctx.

sdcl_service_t const *sdcl_services (sdcl_context_t const *ctx)

  • Returns a pointer to an array of services defined in ctx. The length of the array can be obtained by a call to sdcl_services_count().
